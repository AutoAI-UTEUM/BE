# 리포트 요청 참조의 유일성

SYS-01과 AI-02의 내부 요청 계약을 보완한다.

생성 요청의 dataQuality.criterionEligibility에는 같은 criterionKey를 두 번 넣을 수 없다.
동일 값과 상충 값 모두 거부하여 dict의 마지막 값이 평가 가능 여부를 임의로 덮지 못하게 한다.
조회 요청의 evidence에는 같은 evidenceId를 두 번 넣을 수 없다. 생성 요청과 같은 유일성
경계를 적용하여 한 ID가 여러 fact/sourceType을 가리키는 모호함을 막는다.

모델 호출 전 기존 422 요청 검증 오류로 처리한다. DTO 필드와 정상 요청은 유지되며,
잘못된 참조를 묵시적으로 합치거나 성공으로 처리하지 않는다. 오류에 근거 원문을 추가하지 않는다.
실제 Spring 요청과 저장 경계의 인수는 별도로 확인해야 하며 이 변경은 AI 요청 검증 범위다.
