2. **로컬 수정 완료:** 시험 초안은 첫 생성과 재생성에 각각 전체 타임아웃을 전달했다. 다른 생성 기능처럼 하나의 monotonic deadline에서 재시도 잔여 시간만 사용하도록 보강했다. 10초 미만이면 추가 호출 없이 기존 TIMEOUT으로 종료하며, SCHEMA 외 오류는 새로 재생성하지 않는다. 요청/응답·기본 설정값·프롬프트는 변경하지 않았다.
3. **로컬 수정 완료, Linux CI 확인 대상:** 독립 보안 정적 검토의 PDF 자원 격리·의존 라이브러리 로그 경계 중간 심각도 2건을 보강했다. 요청별 자식 프로세스에 Linux 주소 공간 512MiB·CPU 한도를 적용하고, 기존 120초 parser 예산과 활성 2개/대기 6개 상한을 집행한다. 8,000,000자 초과는 절단 성공이 아니라 기존 EXTRACTION_FAILED로 거부한다. 요청 취소·기동 중 취소·시간 초과·출력 한도 초과에서 child를 종료·회수하고 임시 PDF를 삭제한다. 업로드 staging 취소 누수도 정리했다. pypdf 로그 subtree 억제와 worker stderr 차단으로 문서 조각이 운영 로그에 나가지 않게 했다. 실제 운영 사고를 입증한 것은 아니다.

## 4. 실제 학습 품질 검증안 — 승인 대기

유료 호출 예산과 사용 가능한 자료를 승인받은 뒤 실행한다. 현재 제안은 기존 Optimization 자료로 최대 20 provider 호출이며, 재시도도 동일 예산에 포함한다. 답변을 평가하기 전에 정답·근거 페이지·오류 기준을 작성한다.

제안 판정: 정답/수식의 중대한 오류, 다른 사용자 정보 또는 제출 전 정답 노출, 근거 없는 임상·성격 단정은 1건도 통과시키지 않는다. 그 외 항목은 담당 교사·기획과 평가 척도/통과율을 먼저 합의한다. 이 기준은 아직 팀 승인된 정책이 아니다.

평가 결과는 `자료·페이지·시나리오 / 코드·모델·프롬프트 버전 / 근거 모드 / 첫 본문·완료 시간 / 입력·캐시·출력 토큰·비용 / 정오·근거·검토자`로 남긴다. 학생 실제 답안이나 전체 모델 출력을 운영 로그에 넣지 않는다. 필요 산출물은 승인된 비공개 평가 저장소에 보관한다.

## 5. 미성년자·외부 전송·삭제: Spring/기획에 확인할 것

만 14세 미만 포함 출시는 Discord에서 공유됐으나, 동의 방식·본인/보호자 확인 수단·보존 정책을 AI 코드에서 임의 확정하지 않는다. 법률 적합성 승인으로 이 문서를 사용하지 않는다.

Spring/기획 확인이 필요한 최소 조건:

- 동의 전, 동의 철회 후에는 새 턴뿐 아니라 업로드·백필·요약·리포트·캡션·재시도·대기 작업의 **외부 AI 전송**도 차단하는가? 생성 시작 직전 최신 동의 상태를 확인하는가?
- 이미 실행 중인 작업은 취소/완료 결과 폐기 중 어떤 정책을 따르는가? 철회 이후 늦게 도착한 결과가 다시 저장되지 않는가?
- xAI로 PDF 원본과 파일명, 선택된 페이지 텍스트/이미지, 질문·답안·요약·근거가 전송될 수 있음을 데이터 목록에 포함했는가?
- 파일 삭제 실패/응답 유실은 누가 영속적으로 재처리·대사하는가? 기존 업로드 ID 교체, 자료 삭제, 계정 삭제, 철회 경로를 모두 포함하는가?
- `store=false`를 Files 원본 자동 삭제나 외부 보존 기간의 증거로 해석하지 않는가?
- `EDUPILOT_XAI_FILES_ENABLED=false`는 extract의 부가 업로드만 막는다. 독립적인 `POST /internal/ai/files`와 기존 첨부 호출까지 전부 차단하는 전역 동의 장치로 사용하면 안 된다.
- xAI·운영 로그·평가 산출물의 접근자/보존/삭제 기간, 보호자 검증과 이메일 연락처 확인의 차이를 기획·법무·운영이 확정했는가?

AI는 서비스 내부 토큰을 인증하지만 학생별 권한·동의·DB의 정본은 Spring이다. AI에 boolean 하나를 추가하는 것만으로 전체 동의 수명주기가 완성됐다고 보지 않는다.

## 6. 검증 기록

변경 전 로컬 기준: pytest **959 통과 / 8 스킵**. 스킵은 Docker Compose 실행 파일이 없는 로컬 환경의 설정 회귀 테스트다. 과거 임시 Compose 경로로 재실행한 8건은 `FileNotFoundError`로 실패했으며, 애플리케이션 회귀와 구분한다. 현재 develop CI에서는 같은 8건을 포함해 967건이 통과했다.

실행 명령(실제 모델 미사용):

```bash
cd ai-service
uv run --offline --frozen ruff check src tests demo.py
uv run --offline --frozen ruff format --check src tests demo.py
uv run --offline --frozen mypy src tests demo.py
uv run --offline --frozen pytest -q
```

변경 후: Ruff check/format PASS(148개), mypy **147개 소스 파일 PASS**, pytest **1005 통과 / 9 스킵(14.22초)**. 스킵은 Compose 8건과 macOS에서 실행할 수 없는 Linux 주소 공간 제한 1건이다. Linux CI에서 이 9건까지 통과해야 병합한다. 변경 전 재현 단계에서 새 deadline 주입/로그 키 테스트가 실패하고 변경 후 통과함을 확인했다. 실제 잘못된 CMap을 읽는 pypdf는 합성 비밀 마커를 로그에 남기지만 공유 추출 함수 적용 후 root/child/stderr에 남지 않는 양성 대조 테스트도 포함했다.

독립 읽기 전용 보안 수정 리뷰에서 추가 bypass/회귀 지적은 없었다. 집중 추출/Files 테스트 61 통과·1 Linux 스킵, AnyIO 취소와 기동 중 반복 취소의 child 회수도 별도 확인했다. 공개 필드·기본 모델/토큰 상한·Spring/FE·환경 파일은 변경하지 않았다. 내부 추출의 기존 오류 코드 활용과 한도를 계약/OpenAPI에 명시했다. 일반 동시 업로드 2건은 통과하지만 포화 시 Spring은 자료 FAILED로 저장할 수 있으며 자동 재시도 정책은 새로 만들지 않았다.

이 문서는 PR 전 검증 기록이다. 사용자 승인 범위는 본 변경의 PR→동일 커밋 CI→develop 병합→dev 배포까지이며, 실제 결과/배포 커밋은 이슈 #469와 PR에 후속 기록한다. prod 배포는 포함하지 않는다. 브라우저·Spring·실제 모델을 잇는 신규 E2E, 실자료 부하/복구 훈련, 프로세스 권한 샌드박스를 검증한 것으로 해석하지 않는다.
