# 가입 이메일 소유 확인 (#471)

## 구현 범위

이 브랜치는 가입 이메일 확인 링크 발급·만료·재발급·1회 사용 확정과 확인 전 서버 접근 제한을 구현합니다. LOCAL·Google 신규 가입 모두 BE 확인 링크를 보내고 `PENDING`으로 시작합니다. Google ID 토큰 검증은 기존 인증 경로를 유지하며 이 변경에서 사용자 이메일 상태를 자동 `VERIFIED`로 바꾸지 않습니다. 이메일 확인과 보호자 확인은 독립 조건입니다.

기존 사용자는 V55 적용 시 `UNKNOWN`이고 확인 근거 없이 백필하지 않습니다. 통합 후보의 V58은 적용 시점에 존재하는 계정을 `LEGACY_EXEMPT`로 구분해 기존 이용을 유지하며, 확인 상태와 시각은 바꾸지 않습니다. 이후 신규 계정은 `NEW_SIGNUP`이고 이메일 확인이 필요합니다. DOB 누락이나 UNKNOWN 상태만으로 신규 계정을 기존 예외로 취급하지 않습니다. 로그인·refresh 후 본인 링크를 재요청할 수 있으며 비밀번호 재설정 성공도 자동 이메일 확인으로 취급하지 않습니다. [기존 계정 정책](legacy-account-access.md).

| API | 인증 | 동작 |
| --- | --- | --- |
| `POST /api/auth/email-verification/request` | Bearer | 본인 링크 재발급, 202. 이미 확인된 계정은 추가 메일 없음 |
| `GET /api/auth/email-verification/status` | Bearer | `emailVerification`, `emailVerificationRequired`, nullable `emailVerifiedAt` |
| `POST /api/auth/email-verification/confirm` | 공개 | `{ "token": "..." }`, 성공 200. JWT·refresh·인증 세션 발급 없음 |

성공 응답은 `Cache-Control: no-store`입니다. 새 메일의 FE 경로는 `/verify-email#token=`이며 텍스트와 HTML 링크에 같은 fragment를 사용합니다. GET 요청·메일 보안 스캐너의 링크 열기로 상태가 변경되지 않으며 확인 API의 GET은 405와 `Allow: POST`를 반환합니다. [FE PR232](https://github.com/AutoAI-UTEUM/FE/pull/232)는 초기 HTML·SPA 진입에서 토큰을 메모리로 옮기고 주소를 정리한 뒤, 명시적 버튼으로 기존 POST body를 보냅니다. 구 query 링크는 FE에서 재발급을 안내합니다. 이 변경은 기존 발송 대기 본문을 바꾸지 않으며 배포·readiness 활성화·실제 메일 검증은 별도입니다.

## 상태와 실패

- 32바이트 난수, Base64URL 43자 토큰, 발급 후 30분 만료입니다. DB에는 토큰 SHA-256과 이메일 SHA-256만 저장합니다.
- 재발급은 이전 미사용 링크를 무효화합니다. 사용자 → 토큰 잠금 순서를 통일해 재발급·확정·탈퇴 경합을 직렬화합니다. 동시 확정 중 하나만 성공합니다.
- 만료 경계, 이미 사용된 링크, 탈퇴, 현재 이메일 불일치와 잘못된 토큰은 `EMAIL_VERIFICATION_TOKEN_INVALID`(400)입니다. 계정 상태를 구별해 노출하지 않습니다. 형식 오류는 `VALIDATION_FAILED`입니다.
- 재요청은 사용자당 3회/시간·IP당 10회/시간, 확정은 IP당 10회/15분 제한입니다. 별도 인메모리 limiter이며 프로세스 재시작에 유지되는 한도는 아닙니다. 발송 한도는 #473의 DB 예약 원장이 추가로 적용합니다.
- 확인 상태 `VERIFIED`와 확인 시각은 함께 있어야 합니다. JWT나 캐시 값만으로 확인을 인정하지 않습니다.
- `User`는 실제 변경 필드만 UPDATE합니다. 프로필·설정·비밀번호 변경 트랜잭션이 이전 PENDING 엔티티를 읽었더라도 다른 트랜잭션에서 확정한 확인 상태·시각을 덮어쓰지 않습니다. 확인 상태 전이의 사용자 잠금과 토큰 1회 사용 규칙은 유지합니다.
- 탈퇴는 재인증 전에 사용자 행을 `PESSIMISTIC_WRITE`로 읽습니다. 인증 확정이 먼저 시작했으면 그 커밋을 기다리고 VERIFIED·확인 시각을 함께 초기화하며, 탈퇴가 먼저 사용자 행을 잠갔으면 확정은 탈퇴 커밋 뒤 기존 링크를 거부합니다. V55의 상태·시각 CHECK를 유지하며, #472 Google 탈퇴와 #477 강의실 생성도 같은 사용자 행 잠금을 사용합니다.

## 접근 경계

HTTP 업무 API는 현재 커밋된 DB 상태를 조회합니다. 신규 미확인 계정의 자료·강의실·학습·파일·SSE·퀴즈·노트·리포트 접근을 `EMAIL_VERIFICATION_REQUIRED`(403)으로 거부합니다. V58의 기존 예외 계정은 `UNKNOWN/PENDING`이어도 `emailVerificationRequired=false`로 이용을 유지하며 이를 `VERIFIED`로 표시하지 않습니다. 정지·탈퇴·역할·소유권 검증은 유지하고 관리자 API의 DB 역할 검증 뒤에 이메일 검증을 수행합니다.

로그인·Google 로그인·refresh·활동 갱신·로그아웃·본인 프로필/비밀번호/설정/아바타·정책 동의·탈퇴 및 공개 정책·health는 확인을 완료하기 전에도 사용할 수 있습니다. 상태·재발급 API는 `/api/auth/**`의 공개 규칙에 앞서 명시적으로 인증을 요구합니다.

외부 AI 전송 전에는 쿼터 설정이나 관리자 역할과 무관하게 현재 DB의 이메일 확인 요구 여부를 재확인하고 V58 기존 예외도 같은 DB 상태에서 적용합니다. 턴/질문/진단, 퀴즈 채점, 시험 초안/채점, 자료 추출/캡션/개요/외부 파일 업로드, 리포트/기준 생성, 대화 요약의 실행 경로를 보호합니다. 파일 삭제·외부 AI 파일 정리에는 이 조건을 적용하지 않아 탈퇴 후 정리가 가능하게 합니다. 이 변경은 AI 내부 요청 스키마나 #469의 timeout·관측성 작업을 바꾸지 않습니다.

## 메일·트랜잭션

가입·재발급 토큰과 #473 암호화 outbox 저장은 하나의 호출자 트랜잭션에 참여합니다. 가입 롤백이면 토큰과 발송 작업이 남지 않으며 외부 메일을 호출하지 않습니다. 발송은 commit 이후 worker에서 수행합니다. 원문 토큰은 메일의 암호화 payload에만 포함되고 사용자 응답·로그에 포함하지 않습니다.

`EDUPILOT_MAIL_ENABLED=false`이면 계정은 미확인으로 유지합니다. 실제 발송이 없다는 이유로 확인을 성공 처리하거나 접근 제한을 해제하지 않습니다. worker 실패·UNKNOWN·만료 처리와 키 관리·상한은 [메일 outbox](mail-outbox.md)를 따릅니다.

## 검증과 배포 대기

합성 데이터와 mock 메일·AI·Google verifier로 정상/만료/재사용/이메일 변경/탈퇴/동시 확정/동시 재발급/가입 롤백/기존 UNKNOWN/로그인·refresh/현재 커밋 상태/API·백그라운드 차단을 검증합니다. 실제 MySQL opt-in 검증은 전용 loopback 합성 DB에서만 실행합니다. V55는 기존 UNKNOWN 보존, 상태·시각 CHECK, 토큰 FK를 별도로 검사합니다.

V55는 V53·V54 뒤에 적용합니다. 초기 V55 단위의 기존 UNKNOWN 차단 설명은 V58 이전 경계이며 통합 후보는 V53–V59 순서와 V58의 기존 이용 예외를 함께 검증합니다. 새 필드·테이블·증거·cohort를 유지하고 신규 gate를 보존하는 복구 이미지를 준비합니다. 컬럼 삭제나 승인 백필로 되돌리지 않습니다. 배포 전에 신규 DOB/동의 입력과 FE 확인 화면, 발송 환경/도메인/실제 수신 경로를 준비하고 해당 후보의 영향을 승인받아야 합니다. develop·DEV 적용을 완료했다는 의미가 아닙니다. [FE 전달 계약과 합성 예시](qa/fe-auth-contract/README.md).

실제 SES 수신, 후속 DEV 배포, FE 링크 연동은 미실행입니다. 만14세 미만 보호자 확인·전체 age/AI 동의 경계는 #478/#491의 후속 작업입니다. 일반 복구 가능 자료 원본/렌더30일은 #477에서 확정·구현했으며 목적별 예외·물리 실행과 운영 복원/원장 반출은 별도입니다. 이메일 인증만으로 출시 조건을 충족했다고 표시하지 않습니다.
