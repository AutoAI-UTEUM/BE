# 일반 복구 가능 자료 파일의 30일 보존 (#477)

사용자가 일반 파일 삭제의 보존기간을 30일로 확정했다. 이 단위는 소유자가 `DELETE /api/materials/{materialId}`로 ACTIVE 자료를 직접 삭제하는 경우의 원본 PDF와 렌더 파일에 이를 반영한다. 동작이 다른 탈퇴·동의철회·법정 파기·계정/아바타·외부 AI 파일에 같은 기간을 일괄 적용하지 않는다.

## 반영한 최소 범위

- `edupilot.deletion.general-files.retention-days=30`을 별도 설정으로 바인딩한다. 확정한 기간을 환경설정으로 조용히 바꾸지 못하도록 30 이외의 값은 시작 시 거절한다.
- 자료 논리 삭제와 같은 트랜잭션에서 원본/렌더 `deletion_intents.retain_until`에 요청 시각(UTC) + 30일을 저장한다. 기존 V56 컬럼을 사용하며 새 migration이나 기존 행 추정/backfill은 없다.
- 원장은 `POLICY_PENDING`을 유지한다. 기한 기록이 worker 실행 승인이 되지 않는다. `edupilot.deletion.enabled=false`, 물리 삭제 정책 선택·kind별 기간은 계속 비설정 상태다. 더 짧은 합성 실행 정책으로도 이미 저장한 30일 기한을 단축할 수 없다.
- export/import는 이미 존재하는 `retainUntil` 필드로 보존기한을 유지한다. 원장이 없는 과거 백업에 반출 이력을 재적용해도 이미 정한 기한을 줄이지 않는다. 실제 운영 반출·복원 수행이나 사용자 복구 화면은 이 단위에서 제공하지 않는다.

## 다른 삭제 목적과의 경계

`MaterialService.delete`만 `recordRecoverableMaterial`을 사용한다. `MaterialWithdrawalHook`의 `recordMaterial`, 계정·아바타 원장과 외부 AI 식별자 정리는 미정 목적의 기한을 null로 유지한다. 논리 삭제 API의 기존 권한·응답과 물리 삭제 비활성은 그대로다. 저장 파일을 보존하더라도 삭제된 자료의 기존 접근 차단은 유지한다.

일반 30일 정책 자체는 추가 결정이 필요하지 않다. 남은 결정은 탈퇴/동의철회/법정 파기의 목적별 예외 기간·우선순위, 이미 일반 삭제된 같은 파일에 나중에 예외 요청이 생겼을 때의 처리, 외부 AI 및 계정/아바타 범위, 오래된 목적 불명 원장 분류다. 법정 기간을 추측하지 않으며 그 전에는 물리 삭제 엔진을 활성화하지 않는다.

## 검증

실제 설정 바인딩의 기본30일·임의 변경 거절, 자료 삭제의 기한 저장과 default-disabled worker, 30일 경계 이전 보존/기한 이후 mock 실행, 탈퇴의 기한 미확정 유지, 논리 삭제 rollback 및 빈 원장 복원에서 기한 유지 등을 합성 H2/MySQL에서 검사한다. 실제 학생 파일·외부 AI·운영 백업·물리 삭제를 실행하지 않는다.
