# 보호자 관계·고지·기간 검토안 (#526, #479)

2026-10-06 검토용 초안이다. 채택된 정책·법률 판단·운영 활성화 기록이 아니다. [#532](https://github.com/AutoAI-UTEUM/BE/pull/532) `3343e608fa80dd6bdb5888454ad6fac5b09461ad`의 TEAM_REVIEW 구현과 [양식 10종](guardian-team-review-forms.md)을 전제로 한다. 아래 제안은 설정·DB·권한·실메일에 적용하지 않았다.

## 다시 결정하지 않는 사항

- 첫 출시는 만14세미만을 포함하며 업체 없는 팀 직접 확인을 사용한다. 웹 체크·링크·메일 도착만으로 승인하지 않는다.
- 서비스의 보호자 대상은 승인된 KST 현재 연도−출생 연도 ≤14 기준이다. 이 보수적인 제품 조건을 법령상 만 나이 계산 규정으로 설명하지 않는다. 신규 이메일 gate와 기존 cohort·권한 제한을 유지한다.
- 가입 DOB 직접 수정은 없으며 본인 정정 요청은 접수만 한다. 일반 소유자 직접 삭제 PDF/렌더 30일과 보호자 정보 기간은 별개다.
- 아동이 제공한 미확인·거절 보호자 이름·연락처는 첫 수집부터 최대 5일이며 재발급·보완으로 기산일을 늘리지 않는다.
- 사용자가 지정한 회신함과 검토 계정은 같은 계정이다. 공개 문서에서는 `GUARDIAN_REPLY_INBOX`와 `GUARDIAN_REVIEW_ACCOUNT`로 참조하고 실제 주소는 비공개 인계 자료에 기록했다. 선택은 확정됐으나 기존 ACTIVE ADMIN 여부와 user ID는 미확인이다.
- 발신자는 `no-reply@uteum.com`이다. 지정 회신 계정을 발신자로 바꾸거나 새 관리자 생성·권한 부여를 하지 않는다.

## 관계 확인 절차 제안

법정대리인에게 동의 내용을 담은 이메일을 보내고 명시적 동의 이메일을 받는 경로가 시행령에 제시돼 있다. 아동에게서 동의 확인에 필요한 최소 이름·연락처를 받을 수 있다는 근거도 별도로 있다. 이메일 주소 통제나 아동의 자기신고가 법정대리인 관계를 증명한다는 뜻은 아니다. [개인정보 보호법 시행령 제17조의2](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=02&joNo=0017&lsiSeq=289537&urlMode=lsScJoRltInfoR), [법제처 생활법령정보의 아동 보호 안내](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=2&cciNo=1&cnpClsNo=2&csmSeq=659&popMenu=ov).

검토 담당자가 아래 항목을 실제로 대조하는 절차를 제안한다. 문자열 파서나 미리 선택된 체크는 확인 근거가 아니다.

1. 회신 신청번호와 **현재 신청 차수**를 대조한다. 해당 차수 시작 이후·만료 전 회신인지, 안내 버전·digest·필수 SERVICE와 별도 EXTERNAL_AI 의사가 일치하는지 확인한다.
2. 보호자가 직접 밝힌 성명·관계와 법정대리인 자기확인을 확인한다. 이미 가진 신청 정보와 회신 경로에 모순·대리 입력·타인 계정·분쟁 징후가 있는지 검토한다. 모순이 없다는 사실만으로 관계를 자동 인정하지 않는다.
3. 관계를 판단할 수 있는 최소 근거가 부족하면 `NEEDS_INFORMATION`으로 보류한다. 필요한 이유·항목·수단·파기 조건을 먼저 안내하고, 추가 확인 수단의 적정성이 검토될 때까지 승인하지 않는다. 배우자·교사·친척이라는 표시만으로 법정대리인으로 승격하지 않는다.
4. 신분증·주민등록번호·가족관계증명서 원본을 일괄 수집하지 않는다. 문서 확인이 꼭 필요한 사례의 마스킹·열람 전용·원본 미보관·접근 제한 기준은 별도 검토한다. 현 API의 `evidenceReference`에는 민감한 원문·URL·메일 주소를 넣지 않는다.
5. 지정된 현재 ACTIVE ADMIN이 확인수단·관계 판단·범위·받은 시각을 검토한 뒤 승인/보완/반려를 결정한다. 외부 AI 미동의는 SERVICE 의사를 바꾸지 않으며, 철회·만료·새 정책 digest는 기존 접근 제한에 반영한다.

최소 수집과 필요한 정보 외 동의 거부 안내는 [개인정보 보호법 제16조](https://www.law.go.kr/LSW/LsiJoLinkP.do?docType=JO&joNo=001600000&languageType=KO&lsNm=개인정보%20보호법&paras=1)의 원칙이다. 위 체크리스트는 이 원칙과 서버 계약에서 도출한 운영 제안이며 법정 관계 확인의 충분성을 보증하지 않는다. 지정 계정 하나의 기존 역할 확인과 실제 개별 보호자 관계 확인은 서로 다른 검증이다.

현재 `replyChannel=EMAIL_REPLY` 계약을 기준으로 준비한다. 실제 동의 내용을 담은 발신과 명시 회신을 확보할 운영 경로는 별도 준비 대상이다. `replyContact`는 양식의 회신 안내이며 SMTP Reply-To·자동 수신함 연결이 구현됐다는 뜻은 아니다. 전화 확인으로 바꾸려면 승인된 다른 창구와 현 계약의 `PHONE_CALLBACK`을 별도로 검토해야 하며 이메일 설정에서 전화 예외를 임의 허용하지 않는다.

## 고지문 구성 제안

아동에게는 신청 목적, 담당자가 확인할 때까지의 이용 제한, 문의·취소 방법을 쉬운 문장으로 보여 준다. 보호자에게는 아래 내용을 전체 안내와 회신 양식에 같은 버전으로 제공한다. 서비스별 실제 개인정보 흐름이 확인된 뒤 빈 항목을 채우고 최종 원문 SHA-256을 고정한다.

| 구분 | 최종 원문에 필요한 내용 |
| --- | --- |
| SERVICE | 신청번호/차수, 보호자 확인을 위한 이름·연락처·관계·동의 의사와 실제 수집되는 서비스 정보, 목적·처리 주체·보유/파기 조건, 필수 동의 거부 시의 해당 이용 제한 |
| EXTERNAL_AI | 선택 여부를 따로 받는다. 실제 전송 항목·목적·처리 업체·제공/위탁 및 국외 이전 해당 여부·보유/삭제·거부 영향을 사실에 맞게 기재한다. 미정 항목을 포괄적인 “AI 활용” 문장으로 대체하지 않는다. |
| 기간과 철회 | 첫 수집 기한과 승인 후 증거 최대 보유, 승인 유효기간을 구분한다. 목적 종료 시 조기 파기와 철회·만료 후의 제한, 회신함/외부 제공자/백업 정리 범위를 안내한다. |
| 문의·보완 | 지정 회신 창구, 최소 보완 항목, 불필요한 원문을 보내지 말라는 안내, 담당자 검토 절차와 반려/철회 요청 경로 |

동의는 구체적이고 이해 가능한 내용에 대한 자발적인 의사 표시로 구성한다. [개인정보 보호법 시행령 제17조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=182173). 서비스와 선택 AI 문구·기간을 확정하면 `noticeVersion`, 원문 `noticeDigest`와 전체 정책 `configurationDigest`를 함께 고정한다. 링크는 HTTPS fragment이고 FE는 명시 POST만 수행한다. 동의문 버전만 유지한 채 목적·회신·범위·기간을 바꾸어 과거 승인을 재사용하지 않는다.

## 기간 검토안

아래 숫자는 운영 부담과 제한된 재확인 주기를 검토하기 위한 제안이다. 법정 보존기간이나 기존 승인 결정으로 취급하지 않는다. 합성 테스트 값에서도 운영 기본값을 가져오지 않는다. 공개 예제 manifest의 기간은 계속 `null`이다.

| 항목 | 검토 제안 | 채택 전 확인 |
| --- | --- | --- |
| 링크 TTL | 1시간 (`PT1H`) | 만료·재발급 안내, 기존 토큰 무효화와 재시도 UX |
| 신청 TTL | 4일 (`P4D`) | 담당자 처리 가능 시간. 이미 수집한 미확인 연락처의 첫 수집 5일 기한이 앞서면 그 기한을 우선하며 연장하지 않음 |
| 승인 유효기간 | 90일 (`P90D`) | 만료 뒤 자동 이용 제한과 새 절차 안내를 서비스 운영이 감당할 수 있는지 검토. 장기 일회 승인을 기본으로 삼지 않는 제한된 제안 |
| 승인 증거 최대 보유 | 승인 시점부터 90일 (`P90D`)을 같은 길이의 검토 후보로 제시 | 실제 확인 목적·법적 보존 의무·분쟁 처리 필요와 파기 범위 검토가 먼저다. 코드상 증거 기한은 승인 유효기간보다 짧을 수 없음. 철회·반려·탈퇴에는 목적 종료에 따라 더 먼저 정리됨 |

보유기간 종료 또는 목적 달성으로 정보가 불필요해지면 파기하며 별도 법령의 보존 의무는 구분해야 한다. [개인정보 보호법 제21조](https://www.law.go.kr/LSW/LsiJoLinkP.do?docType=JO&joNo=002100000&languageType=KO&lsNm=개인정보%20보호법&paras=1). 고정 90일의 법적 충분성은 이 자료가 판단하지 않는다. 다른 법적 보존 의무가 확인되면 철회 시 조기 정리하는 현 구현에 필요한 별도 보존 경계를 먼저 설계·검증해야 하며 기간 설정만 길게 늘려 해결하지 않는다.

DB 정리는 실제 외부 회신함의 원문·첨부, 메일 제공자와 백업 사본을 지우지 않는다. 그 사본의 담당자·최대 보유·삭제 방법·실패 모니터링·복원 뒤 재삭제를 같은 정책에 포함해야 한다. 이미 확정된 일반 PDF/렌더 30일, 로그 metadata 기간, 계정 탈퇴 파일과 외부 AI 자료는 각각 별도 목적·정책으로 남긴다.

## 남은 최소 결정과 증거

사용자/정책 담당자가 검토할 항목은 **관계 확인 기준, 최종 고지문과 선택 AI 범위, 위 기간 및 외부 사본 파기 계획** 한 묶음이다. 선택된 이메일이나 업체 없는 경로를 다시 묻지 않는다. 기간 제안의 수용·조정이 있기 전 정책 승인 참조와 활성화 값은 비어 있어야 한다.

운영자가 제출할 근거는 [#532 현재 운영 준비](launch-team-operational-readiness.md)에 있다. 지정 계정의 기존 `id/role/status` 한 건, 정확한 이미지/CI·Flyway·유효 정책 digest, FE artifact/동작, 집계와 보존 계획이 필요하다. 실제 역할 변경·메일 시험·배포 창·복원은 이 검토안을 승인하는 것과 별도로 정해진 실행 범위에서만 진행한다.
