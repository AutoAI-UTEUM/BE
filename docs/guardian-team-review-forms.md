# 보호자 팀 확인 양식

이 문서는 유료 인증업체나 SMS 없이 담당자가 확인하는 `TEAM_REVIEW`의 안내·회신·검토 양식을 설명한다. 양식 생성은 정보 접수와 사람이 판단하는 절차를 보조한다. 웹 링크를 열거나 체크하거나 회신을 접수한 사실만으로 법정대리인 관계를 확인하거나 승인하지 않는다.

실제 동의문, 처리 항목·목적, 확인 절차, 담당자, 승인 후 증거 보존·승인 유효기간이 확정되기 전에는 기능을 활성화하지 않는다. 문구가 비어 있거나 `TBD`, `미정`, 미승인 예시가 남은 상태는 발송 가능한 양식으로 생성하지 않는다. 코드의 입력 검사는 문구의 법적·업무적 검토를 대신하지 않는다.

## 제공하는 양식

`GuardianTeamForms`는 HTML이 아닌 일반 텍스트를 만든다. `FormContext`는 신청 UUID와 양수 신청 차수(`generation`), 동의문 버전·SHA-256 digest·주소, 승인된 안내 문구, 확인 창구, 필수·선택 동의 범위, 신청 만료 시각을 받는다. 아동 이름·생년월일·주소·전체 프로필·토큰은 받지 않는다. 대상 표시는 `신청번호 <UUID>의 이용자`다.

재신청에서 신청번호 UUID는 유지되고 신청 차수는 증가한다. 안내 메일·회신 양식·체크리스트에는 두 값을 자동 표시한다. 같은 신청번호와 같은 동의문 버전의 과거 회신도 차수가 다르면 현재 동의로 재사용하지 않는다. 신청 차수가 없는 회신도 현재 신청의 명시적 확인으로 자동 처리하지 않는다.

| 키 | 사용 시점 | 주요 내용 |
| --- | --- | --- |
| `receipt` | 신청 접수 | 신청번호, 확인 기한, 연락 창구, 접수가 승인이 아니라는 안내 |
| `consent_email` | 동의 내용 안내 | 수집 항목·목적·보유·파기·거부 영향, 동의문 버전·digest, 명시적 회신 또는 전화 확인 안내, 복사할 회신 양식 |
| `reply_form` | 보호자의 회신 작성 | 신청번호·신청 차수·버전·digest 자동 입력, 성명·관계·자기 확인·동의 여부 직접 입력 |
| `review_pending` | 의사 표시 또는 확인 회신 접수 후 | 담당자 검토 대기, 중복 접수가 새 승인으로 처리되지 않음 |
| `approved` | 담당자 최종 승인 후 | 승인 범위, 다른 가입·이용 조건, 문의·철회 창구 |
| `rejected` | 담당자 반려 후 | 이용 제한 유지, 별도 반려 사유 안내, 보유·파기 기준 |
| `needs_information` | 담당자 보완 요청 후 | 필요한 항목만 보완, 불필요한 원본 증거 금지, 최초 수집일·기한 연장 금지 |
| `revoked` | 신청 철회 또는 승인 철회 후 | 철회 범위의 이용·외부 AI 전달 중단, 새 승인에는 새 확인 필요 |
| `expired` | 신청 또는 승인 만료 후 | 만료된 신청·링크로 승인하지 않음, 새 절차 문의 |
| `reviewer_checklist` | 지정 담당자의 상세 화면 | 확인 수단·관계·동의 범위·상태·권한 검토와 최소 감사 항목 |

`renderAll(context)`는 지정 담당자에게 보여 주는 전체 양식 미리 보기용이다. 본인·공개 링크 API는 현재 상태에 맞는 양식만 반환한다. 승인되지 않은 신청 화면에서 `approved` 안내를 표시해서는 안 된다. 반환 문자열은 `textContent` 등 텍스트 방식으로 표시하며, HTML 삽입에 사용하지 않는다.

## 명시적 회신 양식 예시

**아래는 운영 미승인 예시다. 실제 보호자에게 보내는 동의문으로 사용할 수 없다.** 대괄호 안 운영 문구는 실제 서비스 처리와 대조하고 승인된 내용으로 채워야 한다. 수집 항목·목적·보존기간을 이 문서에서 새로 결정하지 않는다.

```text
보호자 동의 확인 안내

신청번호: b920343e-f30e-4ca1-9828-1088ad5bfe70
신청 차수: 1
대상 아동: 신청번호 b920343e-f30e-4ca1-9828-1088ad5bfe70의 이용자
동의문 버전: [검토가 끝난 동의문 버전]
동의문 SHA-256: [해당 동의문 전체의 확인된 digest]

이 안내는 보호자 동의와 담당자 확인을 위한 것입니다.
링크 열기, 웹 체크 또는 회신 접수만으로 관계 확인이나 승인이 끝나지는 않습니다.

수집 항목: [실제 필수·선택 처리 항목]
수집·이용 목적: [실제 기능과 외부 전달을 대조한 목적]
보유·파기 기준: [미확인·거절 정보와 승인 후 증거를 구분한 기준]
동의 거부와 이용 영향: [필수 거부와 선택 거부의 실제 영향]
동의문 전체: [검토가 끝난 HTTPS 주소]
신청 확인 기한: [최초 수집·신청 기록에 따른 기한]
명시적 이메일 회신 창구: [실제 팀 회신 주소]

복사해서 작성할 회신 양식
신청번호: b920343e-f30e-4ca1-9828-1088ad5bfe70
신청 차수: 1
대상 아동: 신청번호 b920343e-f30e-4ca1-9828-1088ad5bfe70의 이용자
법정대리인 성명: [직접 입력]
관계: [부모 / 미성년후견인 중 직접 선택]
법정대리인 자기 확인: [위 아동의 법정대리인임을 확인합니다 / 확인하지 않습니다 중 직접 선택]
동의문 버전: [검토가 끝난 동의문 버전]
동의문 SHA-256: [해당 동의문 전체의 확인된 digest]
필수 동의(SERVICE): [동의합니다 / 동의하지 않습니다 중 직접 선택]
선택 동의(EXTERNAL_AI): [동의합니다 / 동의하지 않습니다 중 직접 선택]

필수 동의와 선택 동의는 별도로 선택해 주세요.
회신 주소를 확인 연락처로 사용하며 별도 주소·전화번호를 추가하지 않아도 됩니다.
주민등록번호, 신분증·여권 사진, 가족관계증명서 원본을 이 양식에 첨부하지 마세요.
```

외부 AI 선택 동의를 구성하지 않았다면 `EXTERNAL_AI` 선택 줄 대신 별도 선택 동의 항목이 없다고 안내한다. `SERVICE`의 고정 식별 라벨은 “서비스 이용에 필요한 개인정보 처리”, `EXTERNAL_AI`는 “외부 AI에 학습 내용을 전송하는 선택 동의”다. 이 라벨은 실제 항목·목적·전달 조건의 안내를 대신하지 않는다.

`PHONE_CALLBACK`에서는 위 양식이 전화 확인 전 읽을 내용으로 제공된다. 담당자는 동의 내용을 안내하고 명시적인 선택을 직접 확인한다. 양식 작성 또는 이메일 접수만으로 전화 확인을 완료했다고 기록하지 않는다.

확인 수단은 현재 운영 설정과 정확히 일치해야 한다. `replyChannel=EMAIL_REPLY`이면 담당자의 `Confirmation.method`도 `EMAIL_REPLY`, `replyChannel=PHONE_CALLBACK`이면 `PHONE`만 허용한다. 이메일 설정에서 전화 확인을 예외로 자동 허용하지 않는다. 다른 수단을 쓰려면 해당 절차와 운영 설정을 별도로 검토해야 하며, 현재 신청의 설정을 무시해서 진행할 수 없다.

## 담당자가 확인하고 기록할 항목

1. 현재 지정 담당자 권한, 신청 상태·세대번호(`generation`)·수정번호(`revision`), 최초 수집일과 기한을 확인한다.
2. 회신 신청번호·신청 차수·동의문 버전·digest가 현재 신청과 맞는지 확인한다. 같은 번호의 과거 차수 회신은 재사용하지 않는다. 신청번호와 차수가 맞아도 발신자나 관계가 확인되는 것은 아니다.
3. 현재 `replyChannel`에 맞는 `EMAIL_REPLY` 명시적 회신 또는 `PHONE` 담당자 전화 확인의 수단, 시각과 제한된 증거 참조를 확인한다.
4. 성명, `PARENT`/`MINOR_GUARDIAN`, 법정대리인 자기 확인, 필수·선택 동의를 구분해 확인한다.
5. 팀이 확정한 관계 확인 절차로 판단한다. 자기 선언·이메일 주소 소유·웹 클릭만으로 관계를 단정하지 않는다. 절차로 판단하기 어려우면 보완 요청 또는 반려한다.
6. 최소 확인 기록을 등록하고 최종 승인·반려·보완 요청을 별도 제출한다. 권한·상태·버전은 결정 트랜잭션 안에서도 다시 확인된다.

| 기록 항목 | 제한 |
| --- | --- |
| 신청번호·세대번호·수정번호 | 서버의 현재 신청에서 선택 |
| 확인 수단 | 현재 설정에 맞는 명시적 이메일 회신 `EMAIL_REPLY` 또는 담당자 전화 `PHONE`; 수단을 임의로 바꾸지 않음 |
| 증거 참조 | 제한된 문자 식별자; 본문·전화번호·원문 URL·토큰을 복사하지 않음 |
| 회신 수신·전화 동의 시각 | 해당 회신이 실제 수신되거나 전화 동의를 받은 시각; 미래나 해당 신청 차수 시작 전 시각을 사용할 수 없음. 담당자의 뒤늦은 검토 시각으로 바꾸지 않음 |
| 동의문 버전·digest·관계·범위 | 현재 신청과 명시적 회신 내용을 대조 |
| 체크리스트 | 신청 일치, 명시적 동의, 자기 확인, 동의문·범위, 확인 수단·관계·연락 창구를 담당자가 확인 |
| 판단·사유 | `APPROVE`, `REJECT`, `NEEDS_INFORMATION`, 철회와 제한된 사유 코드 |
| 담당자·처리 시각·상태 변경 | 서버 감사 이벤트; 회신 원문·연락처·신분증·토큰을 넣지 않음 |

자유서술 증거 원본 업로드와 회신 원문 저장 API는 제공하지 않는다. 개인정보가 포함된 외부 문서 경로를 증거 참조에 넣거나 원문을 감사 로그에 복사하지 않는다. 승인된 관계 확인 절차와 외부 회신함의 접근·파기 관리가 준비되어야 실제 검토를 시작할 수 있다.

## 누락 항목 확인 보조

`GuardianTeamReplyReview.inspect(plainText, context)`는 담당자가 일반 텍스트를 직접 검토할 때 재사용할 수 있는 순수 보조 함수다. 현재 HTTP API나 이메일 수신 connector에 연결하지 않는다. 최대 8,192자, 항목당 최대 320자로 제한하며 숨은 제어문자를 거절한다. 인용된 이전 안내와 미작성 선택 문구는 새 명시적 회신으로 인정하지 않는다.

결과는 인식한 필드, 빠진 필수 항목과 담당자가 확인할 사항이다. 같은 항목 중복, 신청번호·신청 차수·버전·digest 불일치, 불명확한 자기 확인·동의 선택을 표시한다. 과거 차수 또는 차수 누락을 표시해 담당자가 오래된 회신을 확인할 수 있게 하지만, 실제 회신 시각과 현재 서버 신청 기록도 직접 대조해야 한다. 결과의 `requiresHumanReview()`는 항상 `true`이며 누락 항목이 없어도 승인이 되지 않는다. 회신 발신자·관계·동의를 확인하거나 원문을 저장·로그하지 않는다. `<script>` 등 입력은 실행하지 않는 데이터이며 표시 시에도 텍스트로 취급해야 한다.

## 접수·발송·파기 경계

초기 구현은 **복사할 안내 양식과 담당자의 수동 회신·전화 확인 등록**을 제공한다. outbox 생성, 수신 connector, 자동 발송은 제공하지 않는다. 실제 팀 이메일에서 안내·회신을 운영하려면 별도 운영 승인과 외부 회신함의 접근·파기 절차가 필요하다.

`GUARDIAN_TEAM_NOTICE`는 일반 `sendAsync`, 수신자 이력 기록, outbox, worker 발송 경로에서 차단된다. 연결된 합성 또는 향후 내부 사본을 정리하는 코드는 신청 정리와 같은 트랜잭션에서 수신 주소·제목·provider/error 값·암호화 본문·lease를 제거하고 신청 연결을 삭제한다. 전역 quota의 단위·시각은 개인정보 없는 기록으로 유지한다. 삭제된 수신자의 개별 quota 합산은 유지하지 않으므로, 동일 거절·만료 신청의 재발송을 허용하는 근거로 사용할 수 없다.

외부 회신 메일함, provider, 백업과 이미 시작된 네트워크 호출까지 내부 DB 정리로 삭제되었다고 보장하지 않는다. 연결 없는 실제 시스템의 정보를 이번 작업에서 수집하거나 파기하지 않는다.

아동에게서 받은 미확인·거절 보호자 정보는 이번 요구사항의 **최초 수집일부터 5일 이내 파기 조건**과 별도로 관리한다. 링크 만료가 짧아도 개인정보 보관이 허용되는 기간을 뜻하지 않는다. 링크 재발급, 연락처 보완, 검토 대기로 최초 수집일을 새로 설정하지 않는다. 일반 원본 PDF·렌더 30일 보존을 보호자 연락처·회신·확인 증거에 적용하지 않는다. 확인이 끝난 동의 증거와 감사 기록의 실제 보존기간은 별도 승인된 운영 설정이 필요하다.

`approvedEvidenceRetention`은 승인 증거를 보유할 수 있는 **최대 기한**이다. 그 기간 동안 반드시 모든 증거 참조를 보관한다는 뜻은 아니며, 조기 철회·반려·탈퇴 시 목적에 따른 증거 참조와 로컬 사본 정리를 수행한다. 코드의 기술 조건은 `approvedEvidenceRetention >= approvalValidity`다. 두 기간의 실제 값과 법적 최소 보존 또는 예외 보존이 필요한지는 아직 운영 검토가 필요하다. 이 기술 조건을 법적 보존기간의 결정으로 해석하지 않는다.

동의 수단 검토 근거는 [개인정보 보호법 시행령 제17조의2](https://law.go.kr/lsLinkCommonInfo.do?lspttninfSeq=182193)의 이메일 안내와 명시적 회신, 전화 확인 방법이다. 수집 범위·동의 설명·파기 절차는 [개인정보보호위원회 아동·청소년 개인정보 보호 안내서](https://www.privacy.go.kr/front/bbs/bbsView.do?bbsNo=BBSMSTR_000000000049&bbscttNo=20783)와 실제 서비스를 대조한다. 이 코드나 양식을 사용했다는 사실만으로 관계 확인 또는 법적 요건 충족을 보장하지 않는다.

## 활성화 전에 채울 값

- 실제 동의문 버전·SHA-256 digest·HTTPS 주소와, 검토된 수집 항목·목적·보유·파기·거부 영향 문구.
- 실제 팀 회신 주소 또는 전화 확인 창구, 승인된 관계 확인 절차와 담당자 목록. 목록 입력으로 DB 관리자 역할이 부여되지는 않는다.
- 필수 `SERVICE`, 구성할 경우 별도 `EXTERNAL_AI` 문구와 범위, 승인 후 증거의 최대 보유기간·승인 유효기간, 신청·링크 기간. 증거의 최대 보유기간은 승인 유효기간 이상이어야 하며 실제 두 값은 별도 검토한다.
- 외부 회신함·참조 증거의 접근 제한·파기·복구 후 재파기 운영 절차와 실제 운영 시작 승인.

현재 기본 설정은 비활성이다. 테스트의 합성 문구·계정·기간은 위 운영 입력을 대신하지 않는다. 실제 발송·수신 연동·실제 아동 정보·담당자 권한 부여·배포·운영 영구 삭제는 이 소스 구현의 완료 근거가 아니다.
