# 이용약관·개인정보처리방침 검토용 골격 (#415)

> **실제 서비스 약관이 아닙니다.** 아래 각 절은 학교·개인정보 보호 담당자·법무 검토를 위한 초안입니다. V48의 `0.9` 문서는 이 문서로 안내하는 placeholder만 담고 있으므로, 검토된 문구 `1.0` 등록 및 FE 공개 일정 확정 전에는 운영 약관으로 취급하면 안 됩니다. 수집·위탁·국외 이전의 법적 근거와 보존 기간은 아래 표만으로 확정되지 않습니다.

## 이용약관 초안

### 1. 서비스 정의 [법무 검토]

EduPilot은 강의 PDF 기반 설명·질의응답·퀴즈·채점·교정 및 학습 활동 관리 기능을 제공하는 교육 보조 서비스입니다. 제공 주체, 연락처, 적용 대상과 시행일은 운영 주체가 확정해야 합니다.

### 2. 계정과 이용자의 책임 [법무 검토]

이용자는 본인 명의의 이메일 또는 Google 계정으로 가입하고, 로그인 수단을 타인과 공유하지 않으며, 업로드 자료와 답안에 대한 적법한 이용 권한을 확보해야 합니다. 강의자·학습자·관리자 권한 범위, 계정 정지·탈퇴 절차와 이의 제기 경로를 확정해야 합니다.

### 3. 금지 행위 [법무 검토]

타인의 계정·자료 무단 접근, 권리 침해 자료 업로드, 서비스 방해, AI 출력을 이용한 부정행위 등 금지 범위와 조치 절차를 운영 정책에 맞춰 확정해야 합니다.

### 4. AI 생성물의 성격과 책임 [법무 검토]

AI의 설명·답변·퀴즈·채점·교정은 교육 보조이며 오류나 누락이 있을 수 있습니다. 학습·평가·교육상 최종 판단 주체, 이의 제기 및 정정 절차, 서비스 중단·장애의 책임 범위는 별도로 확정해야 합니다.

### 5. 변경과 고지 [법무 검토]

정책 버전, 시행일, 변경 요약을 게시하고 필요한 경우 새 버전 동의를 받습니다. 사전 통지 기한과 고지 채널은 법무 검토 후 확정합니다. 서버는 미동의자의 일반 API를 현재 차단하지 않으며 FE 화면 안내·동의가 선행됩니다.

## 개인정보처리방침 초안

### 1. 처리 목적과 수집 항목 [법무 검토]

| 목적 | 현재 코드·흐름에서 확인한 항목 | 검토 포인트 |
| --- | --- | --- |
| 가입·인증·계정 관리 | 이메일, 이름, 선택 소속, 비밀번호 해시 또는 Google 식별자, 역할·상태, 인증 세션·refresh 토큰 해시 | 보유기간·필수/선택 구분 확정 |
| 학습 서비스 | 업로드 PDF 및 추출 텍스트·이미지, 학습 세션·대화·질문·답안·퀴즈·진도·노트·시험 제출·채점 | 강의자 자료 및 학습자 답안의 권리·보유기간 확정 |
| 보안·운영 | 요청 IP·User-Agent, 정책 동의 시각·버전, 시스템 로그, 메일 발송 이력(수신자·제목·상태, 본문 미저장) | 로그·감사기록 식별자 및 보유기간 확정 |

### 2. 외부 AI 처리·국외 전달 [법무 검토]

설명·질의응답·퀴즈·채점·오개념 교정 및 노트 생성 등을 위해 학습 대화·질문·답안·노트 생성 요청과 업로드 자료의 PDF 텍스트·이미지 또는 원본 파일이 **xAI(Grok)** 측으로 전송될 수 있습니다. 업로드 파일은 xAI Files에 저장되어 서버의 `xaiFileId`로 연계되며, 서비스의 자료 삭제·회원 탈퇴 시 파일 삭제를 요청하는 코드가 있습니다. 삭제 실패의 재시도·잔존 여부와 xAI 자체 보존기간은 별도 확인해야 합니다.

수신국은 작업 지시상 **미국 리전**으로 가정하나 실제 계약·리전 설정·하위 처리자·국외 이전 법적 근거·거부 방법을 운영 주체와 xAI 계약 자료로 재확인해야 합니다. 공개 문구에는 수신자, 국가, 이전 항목·시점·방법, 목적, 보유기간 및 이용자 권리를 확정해 넣어야 합니다. xAI의 최신 보존·삭제 정책 링크: **[운영 계약에 맞는 공식 URL 입력 필요]**. 단순 웹 공개 문서와 계약 조건이 다를 수 있습니다.

### 3. 저장 위치·백업·로그 [법무 검토]

주 데이터베이스·파일 저장 인프라는 AWS 서울 리전을 전제로 운영 설정을 확인해야 합니다. DB S3 자동 백업 **30일 수명주기**는 #408 런북에 정의되었으나 실제 운영 적용 완료 여부를 확인해야 합니다. CloudWatch 애플리케이션 로그 **14일 보존**도 #409 설정의 실제 운영 적용 여부를 확인해야 합니다. 메일 발송 이력은 `email_deliveries`에 수신자·제목·상태를 기록하며 본문은 저장하지 않습니다. 메일·동의 이력·운영 감사 로그의 최종 보존기간은 아직 정책 결정이 필요합니다.

### 4. 보관·파기 현황 [법무 검토: 실제 코드와 일치 여부 재확인 필수]

| 데이터 | 현재 탈퇴 구현에서 확인한 동작 | 아직 확정할 사항 |
| --- | --- | --- |
| 사용자 계정 | `users` 행을 삭제하지 않고 `DELETED` 상태로 변경. 이메일은 `deleted_{id}`, 이름은 고정 문구로 치환하고 소속·아바타 키·Google 식별자·기존 동의 메타를 비움. 비밀번호 해시를 로그인 불가 값으로 교체 | 잔존 user ID와 재식별 가능성 검토 |
| 인증 수단·아바타 | refresh 토큰·인증 세션 전량 폐기, 아바타 파일 삭제 | 외부 캐시·백업 반영 시점 확인 |
| 개인 학습 세션·소유 자료 | 세션과 소유 자료를 **소프트 삭제**. 연계 xAI Files 삭제는 커밋 후 best-effort 요청 | 실제 원본 파일·하위 대화·답안의 물리 삭제/보존 정책 결정 |
| 대화·퀴즈·시험·노트 등 연결 데이터 | 회원 탈퇴 API에서 일괄 물리 삭제하지 않음 | 목적별 보존기간·삭제 요청 처리 방식 설계 필요 |
| 정책 동의 이력 | `policy_consents`는 수정·삭제하지 않으며 탈퇴 후에도 익명화된 `users.id`를 참조 | 법적 증적 보존기간·익명화 수준 결정 |
| AI 사용량·감사/접속 로그·집계 | 일부는 별도 저장되거나 로그 플랫폼에 남음. `ai_usage_log`는 사용자 FK 없음 | 원문/식별자 보존 및 파기 주기 결정 |

이 표는 **현재 구현의 사실 확인표**이지 “탈퇴 즉시 모든 개인정보 완전 삭제”를 약속하는 문구가 아닙니다. 요구되는 파기 범위와 실제 코드가 다르면 정책 공개 전에 별도 구현 이슈로 정합화해야 합니다.

### 5. 이용자 권리 및 연락처 [법무 검토]

이용자의 열람·정정·삭제·처리정지·국외 이전 관련 요청을 받을 관리자 문의 경로, 처리 기한 및 불복 절차를 운영 주체가 확정해야 합니다. 현재 서비스에는 모든 자료를 자동 다운로드·일괄 파기하는 API가 없으므로 없는 기능을 보장하지 않습니다.

### 6. 안전성 확보 조치 [법무 검토]

비밀번호 해시, JWT·역할·리소스 소유권 검증, 관리자 API의 DB 역할 재검증과 구조화 감사 로그, 인프라 접근통제 및 저장·전송 암호화를 실제 배포 설정과 대조해야 합니다. 구체적인 암호화 알고리즘·키 관리·위탁 운영 내용을 확인 후 게시 문구로 확정합니다.

### 7. 적용 대상 [법무 검토]

미성년자 계정과 기관별 데이터 격리는 **현 사용자층·현재 구현 범위에서 해당 없음**으로 가정합니다. 실제 이용자 구성 변경 시 별도 검토와 구현이 필요합니다.
