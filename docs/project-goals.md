# 프로젝트 목표 문서

| 항목 | 내용 |
| --- | --- |
| 상태 | 초안 |
| 마지막 갱신 | 2026-07-31 |
| 검토 대상 | 전 팀 |

## 1. 해결하려는 문제

PDF 중심 학습은 자료를 읽는 행위와 이해 확인·질문·피드백이 분리되어 있습니다. EduPilot은 현재 읽는 페이지를 기준으로 설명, 질의응답, 퀴즈, 채점, 오개념 교정을 하나의 학습 세션에 연결합니다.

## 2. 핵심 사용자

| 사용자 | 목표 | MVP 행동 |
| --- | --- | --- |
| 학습자 | PDF 내용을 이해하고 이해도를 확인한다 | 로그인, 자료 선택, 페이지 학습, 질문, 퀴즈, 진단·교정 |
| 강사 | 강사 계정으로 가입하고 향후 강사 기능의 주체가 된다 | 현재는 학습자와 동일한 학습 기능·소유권 규칙 사용 |
| 관리자 | 사용자와 학습 자료를 관리한다 | MVP 미구현 — role만 예약, 운영 조치는 DB 수동 처리 (`DEC-017` Accepted) |
| 내부 시스템 | 안정적으로 AI 기능과 상태 저장을 연결한다 | Spring-FastAPI 계약 실행, 기록, 오류 처리 |

`INSTRUCTOR` 계정 역할은 DEC-029 초안에 따라 도입합니다. Course·Lecture·Assignment·Notification과 강사 전용 기능·차등 권한은 #102에서 별도 확정하며 이번 역할 구현에는 포함하지 않습니다.

## 3. MVP 범위

### Must

- `LEARNER | INSTRUCTOR` 역할 선택과 JWT 기반 회원가입·로그인·내 정보 조회·회원 탈퇴(DEC-028·DEC-029 Proposed)
- PDF 업로드, 목록/상세 조회, 논리 삭제, 페이지 정보 제공
- 학습 세션 생성, 재진입, 페이지 이동, 종료
- 페이지 설명과 현재 페이지 기반 QA
- AI 설명·QA 응답 스트리밍
- 네 가지 퀴즈 유형 생성 및 제출
- MCQ/OX 규칙 기반 채점, SHORT/ESSAY AI 채점
- 퀴즈 평가 저장, 저득점 진단 질문, 오개념 교정
- 최근 평가 메모리 큐와 반복 패턴 기반 장기 학습자 메모리 승격·반영
- Spring을 데이터/상태 기준 서버로 유지
- Swagger/OpenAPI와 일관된 외부 API

### Should

- Docker Compose 로컬 통합 환경
- GitHub Actions 테스트·빌드 검증
- dev 배포와 health check

### Could

- 학습 분석 화면
- 운영 모니터링/대시보드 고도화
- 관리자 자료/사용자 관리 최소 기능(MVP 이후 — `DEC-017` 이후 개선안 참조)

## 4. 이번 리빌드에서 하지 않을 것

- 실시간 화상 강의
- 교사-학생 실시간 채팅
- 결제
- 복잡한 관리자 통계 대시보드
- 모든 LLM 응답의 완전 자동 검증
- 근거가 한 번만 관찰된 학습 특성의 장기 메모리 확정
- 프론트엔드의 FastAPI 직접 호출
- Spring 내부의 LLM 기반 에이전트 선택
- 합의되지 않은 Course/Lecture/Assignment/Notification 기능 선행 구현

## 5. 기존 접근에서 버릴 문제점

기존 코드가 제공되지 않았으므로 아래 항목은 **리빌드에서 피할 설계 문제 목록**입니다. 실제 기존 프로젝트 문제로 단정하지 않습니다.

- JSON 파일을 영속 데이터의 최종 저장소로 사용하는 구조
- FE, Spring, FastAPI의 책임이 겹치는 구조
- 페이지 이동처럼 결정적인 상태 변경도 LLM 판단에 의존하는 구조
- AI 출력 JSON을 검증 없이 실행·저장하는 구조
- 하나의 턴 실패가 세션 전체 상태를 불일치하게 만드는 구조
- 퀴즈 원본, 제출, 채점, 평가, 진단 기록이 분리되지 않는 구조
- 단일 오답으로 학생 수준이나 오개념을 확정하는 구조
- API 변경이 문서와 프론트 계약에 반영되지 않는 구조
- 민감정보나 프롬프트 원문을 운영 로그에 그대로 남기는 구조

## 6. 성공 기준

- 학습자는 동일한 세션에서 PDF 페이지 이동, 설명, 질문, 퀴즈, 진단·교정을 끊김 없이 수행할 수 있습니다.
- 새로고침/재진입 후에도 Spring과 MySQL에 저장된 상태로 화면을 복원할 수 있습니다.
- FE는 OpenAPI와 화면-API 매핑만으로 Spring API를 연동할 수 있습니다.
- AI 서버가 실패하더라도 데이터 손상 없이 재시도 가능한 오류가 반환됩니다.
- 설명·QA 응답이 스트리밍되고 중단·재연결 시 미완료 메시지가 확정 저장되지 않습니다.
- 반복 근거가 있는 학습 패턴은 장기 메모리로 승격되어 이후 학습 응답에 반영되고, 단일 관찰은 승격되지 않습니다.
- 핵심 시나리오가 자동 테스트 또는 명시적 통합 테스트 절차로 검증됩니다.
