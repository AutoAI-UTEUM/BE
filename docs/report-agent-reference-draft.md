# 리포트 에이전트 설계 참고 원안

> 이 문서는 리포트 에이전트 도입을 위한 최초 요구 원문을 개발 참고용으로 보존한 자료입니다.
> 현재 확정 계약이나 구현 완료 상태를 나타내지 않습니다. 특히 강의실·주차·별도 시험·교사 전용
> 기능은 기존 MVP 범위 밖이므로, 실제 구현은 별도 설계 문서와 승인된 결정·API·migration을
> 기준으로 진행합니다.

# 목차

1. 리포트 에이전트 개요
    - 리포트 에이전트가 필요한 이유와 최종 목적 정의
2. 전체 동작 과정
    - 학습 데이터 수집 → 정리 → 평가 → 리포트 생성 흐름 정의
3. 수집해야 하는 학습 데이터
    - 통합 학습 에이전트에서 발생한 데이터
    - 별도 시험 컨텐츠에서 발생한 데이터
4. 데이터 정리 및 평가 근거 생성
    - 여러 학습 세션의 데이터를 학생별로 연결하고 분석 가능한 형태로 정리
5. 학생 평가 기준
    - 기본 평가 항목과 선생님이 추가할 수 있는 평가 항목 정의
6. 최종 리포트에 포함할 내용
    - 학생의 현재 상태, 강점, 약점, 오개념, 성장 흐름, 다음 지도 방향 정의
7. 리포트 생성 시 지켜야 하는 평가 원칙
    - 근거 없는 판단과 단일 시험 결과에 따른 과도한 평가 방지
8. 선생님 사용 흐름
    - 학생 선택, 리포트 생성, 평가 항목 관리, 추가 질문 흐름 정의
9. 저장 및 접근 제약
    - 학생별 데이터 분리, 권한, 저장본 관리 원칙 정의
10. 핵심 기능 시나리오
    - 실제 시스템에서 반드시 동작해야 하는 주요 상황 정의
11. 성공 기준
    - 리포트 에이전트가 정상적으로 동작했다고 판단할 기준 정의

# 1) 리포트 에이전트 개요

- 리포트 에이전트는 학생이 여러 학습 세션에서 남긴 학습 기록을 한곳에 모아 → 선생님이 학생의 현재 학습 상태를 빠르게 이해할 수 있도록 평가 리포트를 만드는 에이전트
- 선생님이 주로 사용하는 기능이며, 학생이 실제로 어떤 수준으로 공부하고 있는지를 누적 데이터 기준으로 보여주는 것이 목적
- 단순히 시험 점수만 보여주는 리포트 X
    - 통합 학습 에이전트에서의 질문 태도
        - 적극적으로 질문하는가?, 강의 내용에 맞는 질문인가? (의미를 확장하는 질문이면 ok, 그외 이상한 말은 감점 요인)
    - 강의별 진도
        - 진도율은 설명 에이전트가 마지막으로 설명을 완료한 페이지를 기준으로 계산한다.
        - `진도율 = 마지막 설명 완료 페이지 ÷ 전체 페이지 × 100`
    - 통합 학습 중 진행한 퀴즈와 점수
    - 별도 시험 컨텐츠에서 진행한 시험 점수와 문항별 결과
    - 반복적으로 틀리는 내용
        - 별도로 카운트되는 로직이 없다면 빼도 됨
    - 학생이 실제로 헷갈린 지점
        - misConception 에이전트의 피드백을 활용한다
    - 오답 피드백 이후의 변화
        - misConception이후 → 시험 점수가 어떻게 변화했는지를 들고온다
    - 학습 참여도와 최근 성장 흐름
        - 적극적 질문 태도랑, 통합 학습 에이전트 혹은 교사가 임의로 생성한 시험에서 점수의 변화
    - 위 내용을 함께 보고 종합적으로 평가해야함
- 리포트의 기본 단위는 한 명의 학생
    - 같은 학생이 여러 강의와 여러 학습 세션을 진행했다면 → 해당 데이터를 연결해서 누적 평가
    - 필요하다면 같은 원칙으로 강의실 전체의 경향도 따로 볼 수 있어야함
        - 강의실에 속한 여러 학생 데이터를 종합해 → 요약본(평균 성취도, 공통 어려운 개념 등등)을 얻을 수 있어야 함
- 모든 평가는 결과만 보여주는 것이 아니라 → 어떤 학습 기록을 근거로 판단했는지 함께 보여줘야함
    - 근거는 토글 느낌으로 → 누르면 제대로 근거를 볼 수 있게 해줘야함 → 이때 출처로 “~~세션의 ~~주차 강의 ~~페이지 기록” → 이런 느낌으로 진행한다

# 2) 전체 동작 과정

1. 선생님이 강의실과 학생을 선택한다
2. 해당 학생이 지금까지 진행한 통합 학습 세션을 찾는다 → 해당 강의실 안에서 진행된것
    - 만약 선생이 강의실 + 임의 주차 or 임의 통합학습 세션을 선택한 경우 → 그거에 대해서만 진행을 한다
3. 해당 학생이 별도 시험 컨텐츠에서 제출한 시험 결과를 찾는다
    - 이것도 선생님이 별도로 지정한다면 → 지정한 컨텐츠만 불러오고, 기본값은 전체 불러오기
4. 수집된 데이터를 학습 종류별로 구분한다
    - 통합 학습 중 발생한 질문, 진도, 퀴즈, 피드백
    - 별도 시험에서 발생한 답안, 점수, 오답, 채점 피드백
5. 여러 세션에서 중복되거나 분석에 필요 없는 데이터를 정리한다
6. 학습 기록을 시간순으로 정리하고 → 누적 결과와 최근 변화 흐름을 각각 계산한다
7. 기본 평가 항목과 선생님이 추가한 평가 항목을 기준으로 학생을 평가한다
8. 각 평가 결과에 점수, 추세, 설명, 근거를 붙인다
    - 근거 출처를 잘 반영 해야함 → `“~~세션의 ~~주차 강의 ~~페이지 기록”`
9. 강점, 보완할 부분, 반복 오개념, 다음 지도 방향을 포함한 최종 리포트를 생성한다
10. 생성된 리포트를 학생별 저장본으로 남기고 → 이후 다시 불러오거나 새 데이터 기준으로 재생성할 수 있도록 한다

# 3) 수집해야 하는 학습 데이터

### 3-1) 통합 학습 에이전트에서 발생한 데이터

- 학습 세션 기본 정보
    - 어떤 강의실의 어떤 강의인지
    - 몇 주차 자료인지
    - 어떤 학생의 세션인지
    - 마지막으로 학습한 시점
- 학습 진도
    - 전체 페이지 수
    - 실제로 학습한 페이지 수
    - 현재까지 이동한 페이지
    - 강의별 진도 비율
    - 여러 세션에 걸쳐 학습을 지속했는지
- 학생의 질문 기록
    - 질문 수
    - 최근 질문 내용
    - 질문이 어느 페이지와 개념에서 나왔는지
    - 질문이 구체적인지
    - 본인이 헷갈리는 지점을 직접 표현했는지
    - 이전 설명이나 다른 개념과 연결해서 질문했는지
    - 자신의 이해를 확인하려는 질문인지
- 질문 태도는 질문 수만 보고 판단하지 않는다
    - 질문이 많아도 단순 반복 질문만 있다면 높은 평가를 주지 않음
    - 질문이 적더라도 본인이 막힌 지점을 구체적으로 표현했다면 의미 있는 학습 근거로 사용
    - “다음 페이지”, “넘어가줘”와 같은 단순 화면 이동 명령은 질문 데이터에서 제외
- 통합 학습 중 진행한 퀴즈
    - 퀴즈 유형
    - 생성된 페이지와 관련 개념
    - 학생 답안
    - 점수와 정답률
    - 문항별 정답, 오답, 부분 정답 여부
    - 최근 점수가 좋아지고 있는지 또는 낮아지고 있는지
- 오답 진단 및 교정 기록
    - 어떤 문항에서 틀렸는지
    - 시스템이 추정한 오개념 후보
    - 학생이 직접 답한 헷갈린 지점
    - 오개념 교정 이후 추가 질문이나 재시험 결과
- 학습자 메모리
    - 잘 이해하는 개념
    - 반복적으로 어려워하는 개념
    - 반복 오개념
    - 선호하는 설명 방식
    - 학생에게 효과적인 퀴즈 유형
    - 다음 학습에서 집중해야 할 목표
- 학생 반응과 자신감 관련 데이터가 있다면 함께 참고
    - 단, 실제 데이터가 없는 감정이나 태도를 임의로 추정하면 안됨

### 3-2) 별도 시험 컨텐츠에서 발생한 데이터

- 시험 기본 정보
    - 시험 이름
    - 시험이 속한 강의실과 주차
    - 시험 응시 여부
    - 제출 시점과 채점 시점
- 시험 결과
    - 총점과 만점
    - 점수 비율
    - 전체 평균을 계산할 수 있는 유효한 채점 결과인지
- 문항별 결과
    - 문항 유형
    - 문제 내용
    - 학생이 제출한 실제 답안
    - 정답 또는 모범 답안
    - 문항별 점수
    - 정답, 오답, 부분 정답, 미응답 여부
    - 채점 피드백과 오답 설명
- 단답형과 서술형의 경우
    - 단순 정답 여부뿐만 아니라 → 핵심 개념을 어느 정도 이해했는지
    - 답안의 논리 흐름과 근거
    - 루브릭 기준에서 부족했던 부분
        - 루브릭 부분은 자동 생성 or 선생님이 추가할 수 있음 → 해당 부분은 별도 시험 기능 문서 참고
    - 부분적으로 맞았지만 헷갈린 개념이 무엇인지
- 통합 학습 중 퀴즈와 별도 시험 결과는 서로 구분해서 집계
    - 화면에서도 각각 몇 번 진행했고 평균이 얼마인지 구분해서 보여줌
    - 최종 학생 평가를 만들 때는 두 종류의 데이터를 함께 참고

### 3-3) 공통으로 연결해야 하는 정보

- 학생 ID
- 강의실 ID
- 강의와 주차 정보
- 학습 세션 또는 시험 ID
- 기록 생성 시점
- 리포트가 생성된 시점
- 이전에 저장된 리포트가 있다면 이전 결과와 현재 결과의 차이

# 4) 데이터 정리 및 평가 근거 생성

- 수집된 모든 기록은 학생별로 완전히 분리해야함
    - 학생 A의 질문이나 시험 결과가 학생 B의 리포트에 들어가면 안됨
- 같은 학생의 여러 학습 세션은 강의와 시간 순서를 기준으로 연결
- 같은 기록이 여러 경로에서 들어온 경우 중복으로 점수에 반영하지 않도록 정리
- 점수 체계가 다른 시험은 0~100 기준의 비율로 정규화한 뒤 비교
- 누적 결과와 최근 결과를 따로 계산
    - 누적 결과: 학생의 전체적인 학습 상태
    - 최근 결과: 최근에 좋아지고 있는지, 그대로인지, 낮아지고 있는지
- 리포트를 위한 데이터 생성시에 → 강의별로도 간단한 중간 결과를 만든다
    - 질문 수
    - 통합 학습 퀴즈 수와 평균 점수
    - 별도 시험 결과
    - 진도
    - 현재 숙달 상태
- 평가에 사용할 수 있는 데이터의 양을 확인
    - 질문, 채점된 퀴즈, 시험 결과, 피드백, 학습자 메모리가 충분한지 확인
    - 데이터가 적다면 확정적인 표현을 사용하지 않고 “관찰 데이터 축적 중”으로 안내
        - 데이터 충분 여부는, 시스템 내에서 값으로 정의한다 → LLM이 충분, 불충분 파악 X
- 리포트의 각 판단에는 근거 데이터를 연결
    - 예: “분수 나눗셈 개념 보강 필요”
        - 근거: 관련 퀴즈 2회 오답 + 별도 시험 1문항 부분 정답 + 같은 개념에 대한 반복 질문
        - 이때 관련 퀴즈, 별도 시험 등등 → 어디에 있는 부분에서 해당 평가를 가져온건지를 정확하게 명시해야함

# 5) 학생 평가 기준

### 5-1) 기본 평가 항목

1. 개념 이해도
    - 핵심 개념을 정확히 이해하고 다른 개념과 연결하는 정도
2. 질문 구체성
    - 본인이 모르는 지점과 학습 병목을 구체적으로 표현하는 정도
3. 문제 해결력
    - 퀴즈와 시험에서 답을 구성하고 문제를 해결하는 정도
4. 응용 및 전이력
    - 배운 내용을 새로운 문제나 다른 문맥에 연결하는 정도
5. 퀴즈 및 시험 정확도
    - 통합 학습 퀴즈와 별도 시험에서 실제 점수로 나타난 성취도
6. 학습 지속성
    - 여러 세션에서 학습을 이어가고 진도를 꾸준히 진행하는 정도
7. 오답 성찰력
    - 피드백을 보고 본인의 오개념을 확인하고 보완하려는 정도
8. 수업 참여도
    - 질문, 응답, 퀴즈, 진도 등 실제 학습 활동에 참여한 정도
9. 학습 자신감
    - 학습 과정에서 답변과 문제 풀이를 지속하고 최근 결과가 안정되는 정도
    - 단, 별도의 자신감 근거가 없으면 점수만 보고 감정 상태를 단정하지 않음
10. 성장 흐름
    - 최근 점수, 진도, 질문 태도, 오답 교정 결과가 이전보다 좋아지고 있는지

### 5-2) 선생님이 추가하는 평가 항목

- 선생님은 강의실 특성에 맞는 평가 항목을 추가할 수 있어야함
    - ex) 발표 논리력, 협업 태도, 탐구 확장성, 과제 성실도
- 추가 평가 항목은 이름과 세부 설명을 함께 입력
- 이미 존재하는 항목과 의미가 중복되면 안내
    - 시스템적으로 → 단어가 너무 중복되면 빼는걸로 초반 필터링
    - 이후, 레포트 제작할때, LLM이 보기에 너무 의미가 비슷하다면 → 해당 부분 제외하겠다고 별도 알림후, 제거 → 만약 사용자가 그럼에도 원한다면 해당 평가 부분은 계속해서 추가
- 기본 평가 항목은 시스템의 공통 기준이므로 임의로 삭제하지 않음
    - 기본 평가 항목은, 여러 의견을 모아 반복되는 경우가 있다면 수정할 수 있도록 함
- 추가 평가 항목을 변경하면 기존 리포트를 바로 덮어쓰지 않고 → 다음 리포트 재생성 시 반영

# 6) 최종 리포트에 포함할 내용

- 리포트 기본 정보
    - 학생 이름
    - 강의실 이름
    - 분석 범위
    - 생성 시점
    - 분석에 사용한 데이터가 충분한지
- 한 줄 요약
    - 선생님이 학생의 현재 상태를 가장 먼저 이해할 수 있는 핵심 문장
- 전체 요약
    - 현재 학습 상태
    - 최근 성장 흐름
    - 가장 먼저 지도해야 할 부분
- 종합 점수와 현재 단계
    - 점수는 0~100 범위
    - 현재 단계는 관찰 중, 성장 중, 안정권 등 직관적인 표현으로 표시
    - 데이터가 부족하다면 종합 점수를 확정적인 능력값처럼 보여주지 않음
- 분석에 사용한 원천 데이터 요약
    - 강의 수
    - 학습 세션 수
    - 진도
    - 질문 수
    - 통합 학습 퀴즈 수와 평균 점수
    - 별도 시험 응시 수와 평균 점수
    - 피드백 및 오답 교정 기록 수
- 평가 항목별 결과
    - 항목 이름
    - 점수
    - 최근 추세
    - 짧은 평가 내용
    - 판단 근거
- 학생의 강점
- 보완이 필요한 부분
- 반복적으로 나타난 오개념
- 선생님이 참고할 코칭 인사이트
- 다음 학습에서 바로 실행할 수 있는 추천 행동
    - ex) 특정 개념 복습
    - ex) 단답형보다 서술형 문제를 통해 이해 확인
    - ex) 다음 강의 전에 이전 오개념 재확인
- 강의별 학습 상태
    - 강의별 질문, 퀴즈, 시험, 진도, 현재 숙달 상태를 짧게 표시
- 데이터 품질 안내
    - 어떤 데이터가 부족한지
    - 어느 시점 이후의 기록을 사용했는지
    - 현재 평가는 어느 정도 신뢰할 수 있는지

# 7) 리포트 생성 시 지켜야 하는 평가 원칙

- 통계와 실제 기록은 서버에서 계산한 값을 기준으로 사용
- LLM은 수치를 임의로 만들지 않고 → 수집된 근거를 해석하고 설명하는 역할
- 한 번의 시험 점수만으로 학생의 전체 수준을 확정하지 않음
- 한 번의 질문만으로 학생의 성향이나 학습 태도를 확정하지 않음
- 같은 약점이나 오개념이 여러 세션에서 반복되었는지를 우선 확인
- 통합 학습 퀴즈와 별도 시험 결과가 다르게 나타나면 둘 중 하나를 무시하지 않음
    - ex) 통합 학습 퀴즈는 높지만 별도 시험이 낮음
        - 익숙한 문맥에서는 이해하지만 새로운 시험 상황에서 적용이 어려울 수 있다고 해석
        - 단, 실제 문항 근거가 있을 때만 해당 내용을 작성
- 학생의 최근 성장과 누적 성취를 구분해서 설명
- 데이터가 서로 모순되면 확정적으로 판단하지 않고 → 추가 확인이 필요한 항목으로 표시
- 근거가 없는 장점, 약점, 오개념, 감정 상태를 생성하지 않음
- 리포트 문장은 선생님이 바로 이해하고 지도에 사용할 수 있도록 짧고 구체적으로 작성

# 8) 선생님 사용 흐름

1. 선생님이 강의실의 학생 리포트 메뉴로 들어간다
2. 리포트를 확인할 학생을 검색하거나 선택한다
3. 이전에 저장된 리포트가 있다면 먼저 불러온다
4. 새 학습 기록을 반영하려면 리포트 분석을 다시 실행한다
5. 분석 중에는 현재 단계를 표시한다
    - 데이터 수집 중
    - 학생 프로필 구성 중
    - 학습 기록 분석 중
    - 평가 점수 정리 중
    - 리포트 작성 중
6. 분석이 끝나면 최종 리포트를 화면에 표시하고 저장한다
7. 선생님은 평가 항목 관리 화면에서 강의실별 추가 기준을 만들거나 수정할 수 있다
8. 추가 기준을 적용한 뒤 리포트를 다시 생성하면 → 해당 항목도 평가 결과에 포함된다
9. 생성된 리포트에 대해 추가로 궁금한 점이 있다면 리포트 질의응답 기능을 사용할 수 있다
    - 현재 선택한 학생의 저장 리포트와 원천 학습 기록만 참고
    - 다른 학생의 데이터는 참고하지 않음
    - ex) “이 학생이 가장 먼저 복습해야 하는 개념은 뭐야?”
    - ex) “최근 시험 점수가 낮아진 이유를 근거와 함께 알려줘”

# 9) 저장 및 접근 제약

- 리포트는 강의실과 학생 기준으로 저장
- 리포트를 다시 생성하면 최신 학습 기록과 현재 평가 기준을 반영한 저장본으로 갱신
- 생성이 중단되거나 오류가 발생한 리포트는 완성된 저장본으로 처리하지 않음
- 선생님은 본인이 관리하는 강의실의 학생 리포트만 조회 가능
- 학생별 리포트 생성 과정에서 다른 학생의 세션, 질문, 시험 답안이 섞이지 않아야함
- 화면에는 필요한 학습 근거만 표시하고 → 불필요한 개인정보나 전체 대화 원문을 과도하게 노출하지 않음
- 별도 시험 점수와 통합 학습 퀴즈 점수는 저장과 표시 단계에서도 구분
- 데이터가 없는 경우
    - 리포트를 억지로 생성하지 않음
    - “분석할 학습 데이터가 부족합니다”와 같이 다음 행동을 안내
- LLM 분석이 실패한 경우
    - 기존에 계산된 진도, 질문 수, 점수와 같은 사실 데이터는 유지
    - 근거가 있는 기본 요약 리포트를 제공하거나 다시 시도할 수 있도록 안내

# 10) 핵심 기능 시나리오

### 1) 여러 통합 학습 세션이 누적된 학생

1. 학생이 여러 강의에서 설명을 듣고 질문과 퀴즈를 진행한다
2. 각 세션에 진도, 질문, 퀴즈, 피드백, 학습자 메모리가 저장된다
3. 선생님이 해당 학생의 리포트 생성을 실행한다
4. 리포트 에이전트는 모든 관련 세션을 학생 기준으로 모은다
5. 누적 학습 상태와 최근 변화 흐름을 함께 평가한다
6. 선생님은 강점, 약점, 반복 오개념, 다음 지도 방향을 확인한다

### 2) 별도 시험 결과가 새로 추가된 경우

1. 학생이 별도 시험 컨텐츠에서 시험을 제출한다
2. 총점과 문항별 채점 결과가 저장된다
3. 선생님이 리포트를 다시 생성한다
4. 리포트 에이전트는 기존 통합 학습 데이터와 새 시험 결과를 함께 분석한다
5. 통합 학습 퀴즈와 별도 시험 결과를 구분해서 보여준다
6. 같은 개념에서 반복 오답이 확인되면 보완할 부분과 근거에 반영한다

### 3) 데이터가 부족한 학생

1. 학생이 아직 질문이나 퀴즈를 거의 진행하지 않았다
2. 선생님이 리포트를 생성한다
3. 리포트 에이전트는 데이터가 부족하다고 판단한다
4. 현재 확인 가능한 진도와 활동 기록만 보여준다
5. 학생 수준을 확정적으로 평가하지 않고 → 추가 학습 데이터가 필요하다고 안내한다

### 4) 선생님이 평가 항목을 추가한 경우

1. 선생님이 “탐구 확장성”과 같은 추가 평가 항목을 등록한다
2. 기존 리포트는 바로 변경되지 않는다
3. 선생님이 리포트를 다시 생성한다
4. 리포트 에이전트는 기본 평가 항목과 추가 항목을 함께 분석한다
5. 새 평가 항목에도 점수, 추세, 설명, 근거가 표시된다

# 11) 구현 성공 기준

- 한 학생의 여러 통합 학습 세션이 빠짐없이 학생별로 연결되어야함
- 별도 시험의 총점뿐만 아니라 문항별 답안, 오답, 부분 정답, 피드백이 평가 근거로 사용되어야함
- 통합 학습 퀴즈와 별도 시험 결과가 화면에서 명확히 구분되어야함
    - → 핵심은 별도 시험의 결과가 해당 학생 평가시 크게 반영된다고 봐야 하기 때문
- 질문 수만이 아니라 질문의 구체성, 자기 점검, 개념 연결 여부가 질문 태도 평가에 반영되어야함
- 진도, 질문, 점수, 오답, 학습자 메모리를 종합한 평가가 만들어져야함
- 각 평가 항목에는 점수만 있는 것이 아니라 설명과 실제 근거가 함께 있어야함
- 학생의 강점, 보완할 부분, 반복 오개념, 다음 지도 행동을 한 화면에서 확인할 수 있어야함
- 데이터가 부족하면 확정적인 학생 평가를 생성하지 않아야함
- 같은 학생의 새 학습 기록이 생긴 뒤 리포트를 재생성하면 최신 데이터가 반영되어야함
- 선생님이 추가한 평가 항목이 다음 리포트 생성 시 반영되어야함
- 리포트 질의응답은 현재 선택한 학생의 데이터만 사용해야함
- 다른 학생의 데이터가 섞이거나 근거 없는 평가 문장이 생성되면 안됨
