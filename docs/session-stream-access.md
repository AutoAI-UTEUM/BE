# 연결된 학습 SSE의 접근 재확인

`SessionStreamAccessGuard`는 연결 당시 역할을 기록하고 전송 직전에 기존 계정·세션·자료 접근 조건을 다시 확인한다. 계정 상태와 역할은 `UserAccessGuard`, 세션 소유·삭제 여부와 자료 소유/멤버십은 `MaterialAccessService.assertSessionAccessible`을 그대로 사용한다. 새로운 연령·보호자·강의실 공개 정책을 정의하지 않는다.

각 확인은 별도의 읽기 트랜잭션에서 수행한다. 호출 중인 학습 트랜잭션이 과거 계정이나 멤버십을 읽었더라도, 다른 프로세스가 먼저 확정한 권한 회수를 다음 전송 확인에서 관측한다. ready·상태·생각 요약·본문·퀴즈·UI action·완료·오류·heartbeat가 같은 경계를 사용한다. 완료 이벤트의 확인은 연결의 종료 상태를 예약하기 전에 수행하므로, 세션을 COMPLETED로 저장한 정상 완료도 전달할 수 있다.

확인 거부나 DB 조회 실패는 내용을 보내지 않고 연결·heartbeat·상류 AI 스트림을 종료한다. 재시도 가능한 전송 오류로 표시하지 않으며, 권한 상세와 예외 메시지는 전송/종료 로그에 포함하지 않는다. 새 내용이 없는 연결은 기존 10초 heartbeat에서 재확인한다. DB 확인과 네트워크 쓰기는 하나의 전역 원자적 작업이 아니며, 모든 인스턴스가 같은 순간에 닫혔다고 주장하지 않는다.

전송마다 DB 읽기가 추가된다. 자료 소유 경로는 계정·세션·자료 조회, 멤버십 경로는 기존 grant 조회도 사용한다. 네트워크 쓰기 동안 DB 행 잠금이나 연결 Map 잠금을 유지하지 않는다. 운영 부하와 실제 브라우저 검증은 이번 합성 테스트 결과에 포함되지 않는다.

`SessionStreamRevocationJpaTest`는 계정 탈퇴 상태·정지·역할 변경·멤버십/자료 연결 제거·자료/세션 삭제와 오래된 호출 트랜잭션, 정상 terminal delivery를 H2와 전용 MySQL에서 검증한다. `SessionStreamAccessDeliveryTest`는 모든 이벤트의 거부, 상류 취소, 로그 노출 방지와 idle heartbeat 정리를 검증한다. 기존 연결 교체·중복 turn·취소·timeout 테스트도 함께 실행한다.
